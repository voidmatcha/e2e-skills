# Same-skill scanner ablation v1

This is a fresh, same-window development comparison of the reviewer's scanner step, following the broader [tool-enabled workflow experiment](../real-fix-tool-workflow-v3/README.md). The [frozen protocol](protocol.json) uses the same three selected public BEFORE/AFTER repair pairs, `gpt-6-sol` medium, staged skill files, shell tool, source, output legend/schema, disposable sandbox, and 480-second call ceiling in both arms. The `scanner` arm follows the skill normally. The `no-scanner` arm reads the same skill but is explicitly told to skip Phase 1 scanner execution and perform the semantic checks manually. That override is an experimental ablation, **not a supported product workflow**; the changed instruction can affect model behavior independently of scanner output. The balanced 12-call schedule ran sequentially with one fresh call per cell and no reused v3 answers.

All 12 calls completed. Every named E2E spec in the scanner arm had one complete scan and `Summary:`; OpenSearch also received a context-JSON scan on each side, giving eight completed scans total. The ablated arm executed no scanner command. Source workspaces were checked for mutation after every call. Raw events and prompts stay in the local benchmark cache; [results.json](results.json) pins the report and three source-adjudication ledgers by SHA-256.

| Measure | Scanner | No scanner |
| --- | ---: | ---: |
| Exact BEFORE target line and pattern, primary | **3/3** | **2/3** |
| Exact target with correct source-label severity, exploratory | 2/3 | 2/3 |
| Mapped same-pattern AFTER alarms | 0/3 | 0/3 |
| Other predictions: confirmed / false positive / invalid location | 89 / 10 / 1 | 90 / 4 / 2 |
| Reported input tokens (cached subset) | 3,527,038 (3,200,768) | 2,758,115 (2,404,864) |
| Output tokens / summed model-call seconds | 26,521 / 1,087.811 | 22,990 / 854.693 |

Both arms found Growi #16 and Chronograf #2. Scanner found OpenSearch #4a at the assertion lines 61 and 71; no-scanner named the same #4a defect at lines 59 and 69, which only assign the values. Thus the single primary-metric gap is an **exact-evidence-location gap**, not complete failure to recognize that defect family. Conversely, the source-admitted Chronograf instance is **P1**: scanner called its target P0 while no-scanner called it P1. The primary metric was fixed as line-and-pattern detection and does not require correct severity; the stricter severity comparison is explicitly post hoc. The preceding workflow-v3 report likewise counted Chronograf as an exact target hit without testing its severity.

The scanner arm used 27.9% more reported input tokens and 27.3% more summed model-call time. Its noncached input was 326,270 tokens versus 353,251 in the no-scanner arm, so the direction reverses when cached tokens are excluded. Cached tokens are already included in reported input; none of these figures is a billing estimate, and model-call time includes reading and reasoning rather than measuring only scanner runtime. The scanner arm also made more shell calls (144 versus 92). The three [Growi](adjudication-growi.json), [Chronograf](adjudication-chronograf.json), and [OpenSearch](adjudication-opensearch.json) ledgers cover all 117 unique off-target keys across arms. Their counts are prediction events, not independent defects, and the ledgers judge pattern/location truth rather than every predicted severity.

The narrow result is mixed: scanner execution accompanied one better target anchor, but did not improve correct-severity target count and produced more non-target false positives on this run. It does not prove the scanner is beneficial or harmful in general. Selected public cases, one model and repetition, prompt differences intrinsic to an ablation, an extra context scan, structured findings instead of the full prose report, and no sealed release isolation limit the inference. No product rule was changed to chase these results.
