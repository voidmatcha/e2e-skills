# Real-fix candidate feasibility (development only)

This is a source-adjudicated candidate search and a small development probe, **not** a sealed scored corpus or a full-workflow skill-effect measurement. The objective was to find new, source-complete upstream E2E fixes before changing the reviewer. All selected cases are public and already inspected; they are unsuitable as a sealed holdout.

### Fixed-condition development probe, registered before calls

The three primary clusters above received only a **prompt-complete, zero-tool development probe**, not a full scanner/workflow evaluation. The registered conditions were the current worktree's reviewer skill snapshot, `gpt-6-sol` at medium effort, the same numbered source files and output legend in both arms, and the existing holdout runner's enforced JSON schema and isolated credential staging. The `full` arm received the full model-visible skill material; `no-skill` received the shared legend but no reviewer material. Neither arm executed the scanner, browser, repository code, or subagents. The treatment was therefore skill *instructions*, not the deployable skill package.

For each of the three cases, the protocol used the upstream parent and fix snapshots with identical source-file paths and the case's relevant app/config context. It specified three fresh repetitions, each in BEFORE then AFTER order, with arm order `full,no-skill` for odd repetitions and `no-skill,full` for even repetitions: **36 scheduled calls**. No retry or replacement of a failed cell. Primary descriptive readout: exact BEFORE pattern/location hits for `#9` and `#4c–4e` in Vexus, `#7` in the focused-test case, and one consolidated `#10a` chain in the PnL-selector case. Count Vexus's two labels as one cluster; report both per-label and all-label cluster recognition. For AFTER, count only alarms on the mapped changed test slice, not unrelated findings elsewhere in the same spec. Record every output, source/skill/prompt digest, runner identity, input usage, and call time. Incomplete cells make the matrix incomplete. All other findings require separate source adjudication before any precision statement.

This probe can show whether the current wording helps on these already-known development examples, including the scanner-unseen Vexus shape. It cannot estimate generalized skill lift, evaluate scanner benefit, or certify 2.0.0. Product rules and frozen fixpair scores remain unchanged regardless of this result.

Independent source review of the *other* reported findings found genuine unchanged Vexus `#17` direct dropdown actions and a later `#9` fixed sleep, plus AFTER `#5b` forced clicks. It also found genuine unchanged PnL one-shot reads and positional selectors. The same outputs contain errors: full material called Vexus's supported status/error check a `#1` missing-evidence issue; no-skill called declaration-only `let` variables `#19` and fixture `use()` calls `#16`, among other false or mislabeled reports. The PnL `test.fail(!pnlText, ...)` finding remains an out-of-contract concern rather than a confirmed `#5a`; the Focus fixture's broad catch around `await use(contexts[0])` also needs fixture-lifecycle proof before an exact `#3` verdict. The raw findings were not blind-adjudicated before this public-case probe, so **no aggregate precision or whole-report accuracy claim** is made.

Across 18 calls per arm, the reported input usage was 1,060,415 tokens with full material and 311,725 without (**3.40×**); cached input was 137,984 and 167,552 respectively. Output was 20,504 versus 18,780 tokens. Summed per-call elapsed time was 597.086 versus 550.939 seconds (**+8.4%** for full material). Input usage includes cached tokens and is not billed cost; summed call time is not end-to-end workflow latency. This measured cost is substantial for a one-cluster gain in this selected probe, and no scanner or host-workflow benefit is represented.

## Decision

**Three selected clusters across two upstream repositories are insufficient for a general skill/no-skill percentage or a pre/post product claim.** The selection is still post-hoc, the Vexus rule instances are correlated, and the ReactiveTrader #10a fix changes another variable. The registered prompt-only probe offers one positive signal on `#10a`, but leaves the Vexus `#4c–4e` miss unresolved and uses much more input. A future efficacy claim needs more independently sourced, source-complete fix clusters under a stated search boundary, blind adjudication of all positives and clean controls, and a fresh full-workflow paired run. Only a confirmed reviewer failure under that workflow with a false-positive guard should motivate a skill or scanner change. Do not add synthetic examples merely to improve the measured result.
