# Pilot B-S2 Planner Hardening Plan

## Application Overview

Gridfinity Layout Tool (http://localhost:5174) is a drawer-organizer planner. The left panel exposes a "Grid Size" section with Width/Depth/Height numeric steppers that control the physical drawer, which drives a CSS-grid "Gridfinity drawer grid, N columns by M rows" application element in the main canvas where users draw bins by click-drag. Bins can be dragged to a "Stash" panel at the bottom of the canvas. This plan hardens a single frozen scenario (B-S2) about recomputing the grid and reporting a bin that no longer fits after a drawer dimension change, based on live exploration of the app.

## Test Scenarios

### 1. Baseplate/Grid recompute on drawer resize

**Seed:** `e2e/seed.spec.ts`

#### 1.1. B-S2: Changing drawer dimensions recomputes the grid and displaces a bin that no longer fits

**File:** `tests/baseplate/b-s2-drawer-resize-displaces-bin.spec.ts`

**Steps:**
  1. Navigate to http://localhost:5174/ with a fresh browser profile and empty client-side storage.
    - expect: observed: App loads a new layout at a generated URL (e.g. /l/<id>/untitled-layout). The Grid Size panel shows spinbutton 'Drawer width in grid units' = 10 and spinbutton 'Drawer depth in grid units' = 8. The grid application element has accessible name 'Gridfinity drawer grid, 10 columns by 8 rows' (role=application). The Stash region is role=status, name 'Stash', with placeholder text 'Drag a bin here to stash it' and count '—'.
  2. LOCATORS (observed, resolved live in this session): Width control = page.getByRole('spinbutton', { name: 'Drawer width in grid units' }) (also stepper buttons 'Decrease/Increase Drawer width in grid units'). Depth control = page.getByRole('spinbutton', { name: 'Drawer depth in grid units' }) (also 'Decrease/Increase Drawer depth in grid units'). Grid element = page.getByRole('application', { name: /Gridfinity drawer grid, \d+ columns by \d+ rows/ }); its accessible name text encodes the live column/row count -- there is no separate numeric readout element for columns/rows. Bin element on grid = role=button with aria-label pattern 'Bin {W} by {D}, category {Category}', and DOM attribute data-bin-id='<uuid>' (stable identity). Stash container = role=status name 'Stash' when EMPTY, but becomes role=button name 'Stash {N} bins' (expandable header, sibling button 'Clear all') once non-empty -- the role/name is state-dependent, do not hardcode one role. Displaced/stashed bin element = DOM node with role=button, attribute data-staging-bin-id='<uuid>' and title='{W}×{D}×{H}u - {Label or Unlabeled}'; its accessible name is just the size text (e.g. '1×1'), which is NOT unique if multiple stashed bins share a size -- assert via data-staging-bin-id, not accessible name, when more than one bin may be staged.
    - expect: observed: data-bin-id on the grid bin equals data-staging-bin-id on the same bin once it appears in Stash (verified: both were 'mtwur0w8-57aebd77f4' for the same bin before/after displacement), proving identity is preserved (moved, not deleted+recreated).
  3. Draw a 1x1 bin in the rightmost column of the top row: on the grid application, compute cell size from the grid's bounding box (width/10 columns, height/8 rows) and mouse-drag from the top-left corner to bottom-right corner of the cell at column index 9 (0-based, i.e. displayed column 10), row index 0.
    - expect: observed: A new element role=button aria-label 'Bin 1 by 1, category Coral' appears with inline style grid-area: 1 / 10 / span 1 / span 1 (row-line 1, column-line 10). It is selected/pressed. The Bin Properties inspector panel shows heading '1×1 Bin'. Layers summary text changes from '0% filled · 0 bins' to '1% filled · 1 bins'. The 'Fill N gaps' button label changes from 'Fill 80 gaps' to 'Fill 79 gaps' (80 = 10x8 cells). The right-panel 'Bin List' region now lists one row (Coral 1x1).
  4. Shrink the drawer WIDTH by exactly one unit using EITHER: (a) click the 'Decrease Drawer width in grid units' stepper button once, OR (b) fill the width spinbutton with '9' and then blur it (e.g. Tab or click elsewhere) -- do NOT assert on state read immediately after fill() without a blur/commit.
    - expect: observed (stepper path): Grid application accessible name changes to 'Gridfinity drawer grid, 9 columns by 8 rows'. The bin button (data-bin-id) disappears from the grid entirely -- the grid's only child becomes the empty-state placeholder 'Click and drag to draw a bin' again.
    - expect: observed (fill+blur path): Immediately after page.getByRole('spinbutton',{name:'Drawer width in grid units'}).fill('9') and BEFORE blur, the grid aria-label is still '...10 columns...' and the bin is still present (data-bin-id query returns true) -- the recompute has NOT happened yet. Only after .blur() (~within one animation frame, observed stable after a 300ms poll) does the aria-label update to '...9 columns...' and the bin disappear from the grid. CONCLUSION: the width/depth spinbuttons commit on blur (or presumably Enter/step), not on every keystroke; tests must trigger blur before asserting.
    - expect: verification condition: assert grid application aria-label reads 'Gridfinity drawer grid, 9 columns by 8 rows' (columns decremented by exactly 1, rows unchanged).
    - expect: verification condition: assert no element with role=button and aria-label starting 'Bin ' remains on the grid application (bin fully removed from the drawable surface, not just visually clipped/hidden while still occupying grid DOM).
  5. Inspect the Stash panel after the width shrink.
    - expect: observed: Stash trigger changes from role=status name 'Stash' to role=button name 'Stash 1 bins' [expanded], with a sibling 'Clear all' button. A stash bin element (data-staging-bin-id) appears with the SAME id value as the grid bin's data-bin-id prior to removal, title='1×1×3u - Unlabeled'.
    - expect: verification condition: assert Stash trigger accessible name is exactly 'Stash 1 bins' (count matches number of newly displaced bins) and NOT 'Stash' (do not use a fixed selector for the empty-state status role, since the role itself changes).
    - expect: verification condition: assert the data-staging-bin-id of the new stash entry equals the data-bin-id the removed grid bin had, to prove it is the SAME bin object (identity), not a newly created placeholder.
  6. Check side-effects that should also be asserted (things that must change, in addition to the bin's location).
    - expect: verification condition: Layers summary text updates from '1% filled · 1 bins' back to '0% filled · 0 bins' (the displaced bin no longer counts toward the layer's fill stats).
    - expect: verification condition: 'Fill N gaps' button label recomputes to the new empty cell count for the shrunk grid (observed: 'Fill 72 gaps' for a 9x8=72-cell empty grid after removing the 1 bin), i.e. it must reflect the NEW grid area, not the old one.
    - expect: verification condition: The right-panel 'Bin List' region reverts to the empty state ('No bins to print' / 'Add bins to the grid to see the print list') -- observed: stashed bins are excluded from the print/Bin List, only grid-placed bins are counted.
    - expect: verification condition (state that must NOT change): the bin's Category assignment is preserved -- observed the Categories panel's '1 bin(s) use this category' counter for Coral remained '1' both before and after the bin was displaced to stash, i.e. category usage counts stashed bins too and is not reset.
    - expect: verification condition (state that must NOT change): the measured/physical drawer dimension readout ('Edit measured drawer dimensions' button text) updates consistently with the new width, e.g. observed it changed from '420 × 336 × 84 mm' to '378 × 336 × 84 mm' (378 = 9 * 42mm grid unit) -- assert this recomputed value, not just the unit-count spinbutton, to confirm the physical-units derivation also recomputed.
  7. Undo the drawer width change via the 'Undo (Ctrl+Z)' button (role=button, accessible name 'Undo (Ctrl+Z)').
    - expect: observed: A single Undo click fully reverts BOTH the grid size AND the bin displacement atomically: grid aria-label returns to 'Gridfinity drawer grid, 10 columns by 8 rows', the bin button reappears on the grid at its original grid-area (1 / 10 / span 1 / span 1) and is re-selected/pressed, and the Stash reverts to the empty role=status 'Stash' state ('—' placeholder). This confirms the width-change-plus-displacement is recorded as ONE history entry, not two separate undo steps.
    - expect: observed: a transient aria-live='polite' region (role=region and a duplicate role=status) briefly renders the text '↩ Undid: Updated drawer' immediately after clicking Undo -- this text is emitted only in response to Undo/Redo button clicks, not after the original direct stepper/blur action (see Limitations).
    - expect: verification condition: 'Redo (Ctrl+Y)' button becomes enabled after Undo; clicking it re-applies the width shrink and re-displaces the same bin (same data-bin-id/data-staging-bin-id), and emits '↪ Redid: Updated drawer' in the same live region.
    - expect: verification condition: after Undo, the Undo button itself may remain enabled (there is an earlier 'create bin' history step) -- do not assert Undo becomes disabled after a single Undo unless the bin-creation step was also undone.
  8. Repeat an equivalent check for DEPTH instead of width, since the two axes were NOT observed to behave symmetrically.
    - expect: observed: with two 1x1 bins present at grid-area row-line 1 (top, as encoded in the DOM 'grid-area' style) and row-line 8 (bottom) respectively, shrinking DEPTH from 8 to 7 (via fill('7')+blur on the depth spinbutton) displaced the ROW-1 bin to stash and SHIFTED the row-8 bin's grid-area to row-line 7 (i.e. it survived, renumbered) -- the tool trims/renumbers rows from the row-1 end.
    - expect: observed: by contrast, with two 1x1 bins at column-line 1 and column-line 10, shrinking WIDTH from 10 to 9 displaced the COLUMN-10 bin and left the column-1 bin's grid-area completely unchanged (2 / 1 / span 1 / span 1, same as before) -- the tool trims columns from the highest-index (rightmost) end without renumbering the surviving bin.
    - expect: verification condition: do NOT assume a single 'far edge' rule applies to both axes. For a WIDTH-shrink test, place the probe bin at the LAST column (index = current width). For a DEPTH-shrink test, place the probe bin at ROW 1 (the first/lowest-index row), not the last row, to reliably trigger displacement; a bin placed at the last row will instead be shifted (renumbered) and remain on the grid.
    - expect: verification condition: when a surviving bin is renumbered (depth-shrink case), its data-bin-id must remain unchanged and only its grid-area row-line should decrement by the amount trimmed -- assert identity + position together, not just count of bins remaining.
  9. Timing/settle gates to use in real assertions (avoid arbitrary sleeps).
    - expect: verification condition: after committing a width/depth change (stepper click, or fill+blur), wait for the grid application's accessible name (aria-label) to match the expected 'N columns by M rows' string before asserting bin presence/absence -- this label update is the most direct, purpose-built settle signal observed for the recompute (Playwright's toHaveAccessibleName / auto-retrying getByRole(...).evaluate poll is sufficient; no fixed timeout was required beyond default auto-waiting in manual testing, a 300ms poll was enough but should not be treated as a hard requirement).
    - expect: verification condition: after asserting the grid label, separately wait for the Stash trigger's accessible name to contain the expected bin count (e.g. 'Stash 1 bins') before asserting on data-staging-bin-id, since the stash header re-render (status->button role change) is a second, distinct DOM update.
  10. LIMITATIONS -- document what the app does NOT provide for this scenario.
    - expect: limitation: there is no toast/snackbar/alert (no role='alert' element) announcing 'bin no longer fits' or naming the displaced bin at the moment of the direct width/depth change. The only textual indication is the Stash header's count changing (e.g. 'Stash' -> 'Stash 1 bins') and the bin's disappearance from the grid/Bin List -- confirmed by querying all [role=alert],[role=status],[aria-live] elements immediately after a direct stepper/fill+blur change and finding none referencing the bin or the displacement.
    - expect: limitation: the '↩ Undid: Updated drawer' / '↪ Redid: Updated drawer' aria-live announcement exists ONLY as a side effect of clicking the Undo/Redo buttons themselves (it is a generic history-log message, not specific to 'bin displaced'); it cannot be used as a real-time signal for the original resize action, only for undo/redo actions.
    - expect: limitation: the stash bin's accessible name is just its size (e.g. '1×1') with no unique per-instance label unless the user has set a custom label -- tests needing to disambiguate multiple stashed bins of the same size must rely on the data-staging-bin-id attribute (or the title attribute, which includes height and label), not on getByRole name matching alone.
    - expect: limitation: I did not find a distinct 'reason' UI (e.g. no message like 'removed because it no longer fits') -- the app reports the displacement purely structurally (bin moved from grid DOM to stash DOM), not textually/semantically.
