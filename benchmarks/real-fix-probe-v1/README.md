# Public real-fix reviewer probe v1

This is a preregistered **development probe**, not a sealed release holdout or a measurement of the runnable scanner. Its fixed configuration is in [protocol.json](protocol.json). It uses the six independently source-adjudicated non-#9 clusters in [acquisition v9](../real-fix-acquisition-v9/cases.json) and [v10](../real-fix-acquisition-v10/cases.json). Each upstream parent and fix source is fetched read-only by pinned commit and its spec Git blob verified. The twelve BEFORE/AFTER packets are shown separately, with no PR, commit, paired source, or repair explanation in a model prompt. The staging tool executes no upstream code.

Freeze one Codex `gpt-6-sol` repetition, medium effort, native enforced JSON output, five-minute call timeout, and the deterministic per-case arm rotation before any model call. The three arms are `no-skill` (more precisely, shared output-legend-only baseline), `catalog-only`, and `full` model-visible skill material. All arms receive the identical source packet, output schema, line numbers, and legend. The current general holdout legend lacks base `#4`, so append the same protocol-only `#4` output label to **all** three arms; do not relabel DataGrok as `#4a`. The `full` prompt does **not** execute the scanner, browser, or subagents. This measures zero-tool instruction effects, not full product behavior.

Primary descriptive endpoint: exact pattern and causal-line target detected on BEFORE, one vote per repair cluster. Secondary endpoints: a mapped same-pattern alarm near the repaired target on AFTER, per-arm total and per-call input/cached/output/reasoning tokens, and summed call time. Do not treat unadjudicated off-target findings as false positives or report whole-report precision. Any incomplete cell makes the matrix incomplete; do not silently retry or impute. One repetition and six selected public clusters cannot estimate population lift or demonstrate cost efficiency.

The six frozen target anchors are base `#4` DataGrok lines 437–439, `#16` Growi line 29, `#4a` OpenSearch lines 61 or 71, `#2` Chronograf line 139 (P1 instance), `#10d` ONEARMY line 31, and `#4i` Kibana beforeEach line 75 only. Each AFTER guard is restricted to the corresponding changed range; Kibana's separate test-local spinner check is not a label. Public source contents are staged in disposable directories and excluded from the committed report.

Run `python3 scripts/evals/run-real-fix-v9-v10-probe.py --runner-path /absolute/path/to/codex --output /durable/path/report.json`. `--plan-only` validates sources and prints the frozen schedule without model calls. The report is written incrementally outside this repository. Use its saved SHA-256 digests and cell records to audit any descriptive summary.

## Outcome

The frozen one-repetition matrix completed **36/36** scored calls on Codex `gpt-6-sol` / `codex-cli 0.159.3`. [results.json](results.json) contains the exact aggregate, per-case strict hits, input snapshot hashes, and local raw-report digest. The raw model report remains in the local cache; it is not archived in this repository, so the published summary alone is not an independently replayable transcript.

| Arm | Exact BEFORE target hits | Mapped AFTER alarms | Input tokens, cached included | Sum of model-call time |
| --- | ---: | ---: | ---: | ---: |
| Full skill material | 5/6 | 0/6 | 724,175 | 565.9 s |
| Catalog only | 4/6 | 0/6 | 469,205 | 456.5 s |
| Output legend only | 1/6 | 0/6 | 225,043 | 380.7 s |

The full arm's one extra hit over catalog-only was Chronograf's missing toggle postcondition. Both guided arms found the OpenSearch invariant sort and the Cypress async hook and absence-only spinner, while all three arms found Growi's missing `await`. **DataGrok is unscoreable under this output contract**: the source-adjudicated label is base `#4`, but the enforced JSON schema omitted `#4` even though the prompt legend appended it. All three arms cited the assertion as `#4a`; the schema forbade the correct answer, so that is not evidence of an independent model subtype error. The table preserves the historical six-case output, but valid strict-recall comparison uses the other five cases: full **5/5**, catalog-only **4/5**, legend-only **1/5**. The full arm used **1.54×** catalog-only input tokens and **1.24×** its summed call time across all six packets; against the legend-only arm, **3.22×** input tokens and **1.49×** time. Input includes cached tokens and is not a billing-cost ratio.

This gives a narrow positive development signal for the skill's model-visible instructions, especially the semantic #2 case, but **does not establish general skill lift or efficiency**. There is one run per cluster, and 183 full-arm, 144 catalog-arm, and 97 legend-arm other findings were not independently adjudicated. Those counts are *not* false-positive counts; whole-report precision is unknown. No scanner ran, the output-legend baseline is not unprompted, and the public selected cases are not sealed. The DataGrok schema error further narrows the valid comparison to five clusters. The next decision should weigh a repeated source-complete run and full finding adjudication before using this as an accuracy or cost claim.
