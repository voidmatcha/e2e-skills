# Changes after the independent review (pre-freeze)

This protocol was not frozen when these changes were made (`freeze.json` does not exist), so they edit the draft files. After `freeze` no file it binds may change. All work was offline: unit tests on synthetic streams and read-only runs over the stored cells of the finished model claude-sonnet-5-5. No model call, container, browser or listening port.

| Finding | Change | Files |
|---|---|---|
| F1 fidelity classifier counted mentions as executions | Steps are counted only for executed commands. The Bash text is split quote-aware into simple commands (here-document bodies removed, assignments and wrappers such as env, timeout, npx and `npm|pnpm|yarn exec` skipped, `bash -c` parsed recursively, `bash -n` ignored); scan.sh, run-preflight-target.sh, `playwright test` and the exploration tools count only as the program or the script of a shell or interpreter. The working directory is tracked per agent across Bash calls, so a `cd` in one call and `cat` in the next, or `cat *.md` after a `cd`, resolves to the skill directory; a reference file needs the Read tool or a read verb (cat, sed, head, tail, grep ...) and a path that names the skill directory, starts with a shell variable or resolves through the tracked directory (ls and echo are not reads). An independent review needs an Agent spawn after the first spec write that names e2e-reviewer or V6 (or a reviewer subagent type), or an e2e-reviewer Skill call made by a subagent after that write; a bare "review" is recorded separately. The looser mention counts stay as separate fields (`scan_sh_mentions`, `playwright_test_mentions`, `preflight_mentions`, `exploration_mentions`, `hot_refs_mentioned`, `review_mentions_after_write`). Negative controls for cat, ls, echo, grep, `bash -n`, here-document text and a generic "review" spawn, positive controls for the usual execution forms, and the cross-call `cd` cases are unit-tested. On the stored sonnet cells every audited count is unchanged (no stored cell was spoofed), and exec counts of `playwright test` exceed the per-call mention counts only because one call can run several tests. | adapter, protocol.json, README, tests |
| F2 cross-family view mapping | Claude `as_treated` is paired with the Codex `as_treated` view (read from its in_view and set_as_treated: A official-tool, B reviewed an official-tool cell and ran its reviewer steps, C core steps, every arm gated). Claude `itt` is paired with Codex `itt`. The Codex `primary` view gates arm A (and B through its source) and leaves arm C ungated, so it is listed only as a separately labelled analogue (`itt/primary`). README, protocol.json (`views.mapping_to_codex_v2`, `pooled_analysis.view_mapping_to_codex_successor`, `combination_with_codex`) and the summary header corrected; `codex_task_diffs` replaced by `codex_cells` with explicit semantics for the three views. The test builds Codex-shaped cells and asserts that the three views select different cells and give different differences, and it checks the view names against the Codex runner when that file is present. | runner, protocol.json, README, tests |
| F3 discordance promised, not computed | `discordance()` and a summary section: per contrast, the views whose cross-model verdict differs from itt's; per model, the views whose label differs. Also written to summary.json. Tested. | runner, tests |
| F4 campaign guard asymmetric | The guard reads `ps` and matches the argument vector (runner script of v1, v2-codex or v2-claude immediately followed by drive, run, preflight, init-check or harness-check), and excludes this process and its ancestors, so a `timeout` or `bash -c` wrapper of the process itself no longer triggers it. README softened: the Codex runner's own guard is another builder's file and does not list `-claude`; complete protection needs both aligned (owner decision below). Tested with a synthetic process list. | runner, README, protocol.json, tests |
| F5 timed-out cells dropped from the cost ratio | A call killed at the wall-clock limit now carries a lower-bound token record from the assistant usage fields of the stream (parent and subagents, one entry per message id; streamed output counts are partial; USD unknown and counted as 0). Such a cell stays in quality per 100k tokens, flagged `lower_bound`; the cost table prints timeouts, their seconds and the lower-bound cell count per arm. Tested, including the call path with a faked timeout. | adapter, runner, protocol.json, README, tests |
| F6 selector decomposition in-sample and loose | The reader now looks at selector literals only (first argument of locator, $, $$, querySelector, click, fill and similar, or a literal that as a whole is a CSS selector), strips `${...}` interpolations of template literals, and does not count a substring attribute selector (`*=`, `^=`, `$=`) when a surviving name in the refactor's replacement text contains the token. A dynamic-selector hint is stored per cell and counted among the clean cells naming none. README, protocol.json and the decomposition text state that the reproduction (8 of 8 failing, 25 of 25 surviving on the stored sonnet cells) is in-sample, that the split is true by construction and that the audit's own 23 and 62 were not re-derived. The stored-cell split is unchanged with the stricter reader. Known residual false positive: a prose literal that reads as `word.token` is treated as a selector. | runner, protocol.json, README, tests |
| F7 secondary refactors not blind, validation blind spots | `refactors.json` now carries `provenance` (written after the stored sonnet specs and transcripts had been read; not blind) and `validation_limits` (initial route only: the v2-23 dialog, the v3-09 study view and every wrapper created from script are not validated). README and protocol.json limits say the same. Not changed: no interaction steps were added to `validate-refactors` (needs a live host run to be trusted). | refactors.json, README, protocol.json |
| F8 pre-freeze path not enforced | `init-check` now stores the CLI version, the model and the raw init events per arm. `drive` refuses unless a stored result matches the installed CLI string, has all three arms and passes the isolation contract under the current `skills.bundled_allowed`. An isolation violation is now flagged fatal: the campaign stops after that call (no second attempt). Early kill while streaming was not built (not testable offline). | adapter, runner, protocol.json, README, tests |
| F9 bundled-skill context asymmetry | README and protocol.json limits name it. Per cell, `unintended_skill_calls` and `skill_call_errors` (denied or failed Skill calls) are recorded and counted in the fidelity table. | adapter, runner, protocol.json, README, tests |

Tests: 110 pass (91 before). `review.sh` and `pre-push-security.sh` are run after the edits (see the build report).

Not changed, owner decisions:

- Aligning the Codex runner's campaign guard (`-claude`) is the Codex builder's file; until then a Codex driver can start while a Claude one runs.
- The `drive` gate compares the exact `claude --version` string; a harmless CLI patch upgrade after init-check needs a new init-check.
- Whether the independent-review rule should also accept a spawn that names neither the reviewer skill nor V6 but is clearly a review (currently it does not count).
- Early abort of a call on a first-init violation (stream parsing during the call); the cost of a violation is now one call.
- Interaction-reaching validation of the hidden and script-created nodes in `validate-refactors`.

Not verifiable offline (unchanged from the build report): the real behavior of the Skill tool and allow-rule syntax, the MCP env reaching the app process, the `--setting-sources project` skill list, bundled skills in init, and every live item in the README.

## Coexistence with the Codex v3 container campaign and the Codex v3 lessons (pre-freeze, still unfrozen)

All work was offline: unit tests on synthetic streams, the stored v1 `claude-sonnet-5-5` transcripts (read only) and the sources and protocols of the other campaigns (read only). No model call, container, browser or server.

| Change | Files |
|---|---|
| The guard refuses only for a TRUE conflict: another Claude-family driver (this runner, v1), a Zeppelin-using driver (oss-eval, thin-eval, loop), the same or a nested output root, a host port range that overlaps this campaign's exact ranges or a socket already listening inside them, or an unclassified `run-generator-*` driver (fail closed). A running Codex container driver (v2, v3, v4, ablation) is not a conflict. The previous guard matched only v1, v2-codex and v2-claude, so it could not see the v3 or v4 Codex drivers at all. Matching is by argument vector with a python interpreter before the script. `score`, `score-secondary` and `validate-refactors` now take the same lock and guard. `guard`, `status`, `verify-config` and `canary` are new offline verbs. | runner, tests, README, protocol.json |
| `port_plan` derives the exact port ranges of the full 36-cell schedule from the engine's own consumption (worst case: every scored run retried once). The offline test replays the engine with a fake test run and counts the ports, then derives the Codex v3 ranges for its 72-cell schedule from its source and protocol and asserts that both sets, and the hull of every other known driver, are disjoint and below the ephemeral range. It also checks that the Codex runners' pgrep patterns do not match this runner and that the Zeppelin helper's driver probe does (the documented reason for the Zeppelin conflict). | runner, tests |
| Strict fidelity as in the Codex v3 harness: a generator or browser MCP call counts only when it completed; attempted and denied calls are recorded apart; arm A cells carry the classes `official-tool`, `manual-follow`, `unverified`, `blocked`, `aborted` (B carries its source's) and `minimal_generator_use`; `.playwright-mcp/` snapshot files are counted as `mcp_artifact_files`, not as out-of-scope writes. | adapter, runner, tests, protocol.json, README |
| Cost and compliance: the full final message is kept (the 3000-character cap is gone); `modelUsage` is cross-checked against the stream (subagent messages included) per call and counted in the tables; on the 36 stored v1 cells, 13 of them with subagent messages, modelUsage covers the stream in every one. | adapter, runner, tests |
| `host_pressure` (1-minute load, swap used and total) is recorded at the start of every cell: the load threshold of 40 is blind to a 10-core host that swaps. Informational. | runner, tests |
| `verify-config` builds one real cell per arm and checks the content that the loaded configuration produces (staged files, split-port transform, installed skills against the repository tree, argv, call environment, scoring path). `canary` reads the first arm A and arm C cells (preflight records or final.json) and answers pass, fail or pending: arm A needs completed generator_setup_page and generator_write_test calls and no 'already used' port error in its verification run; arm C needs the real skill through the Skill tool with an executed preflight and exploration step; modelUsage must cover the stream. | runner, tests, protocol.json, README |

Not changed: the protocol constants, the schedule, the prompts, the scoring path, the split-port design and the real-skill install were already in place and are unchanged. The Zeppelin helper's driver probe (which pauses on this runner) and the Codex runners are other builders' files and are not edited.

Not verifiable offline: that Claude Code passes the MCP config env to the MCP server, the real behaviour of the Skill tool allow rules, whether the MCP browser keeps a persistent profile directory, and the official initializer inside `verify-config` (it runs `npx --no-install playwright init-agents`, a local file-writing command, and was not run here).

## Repair after the independent review of the operator and canary (pre-freeze, still unfrozen)

Offline only; no model call. The operator script lives outside the repository and is described here for the record.

| Finding | Change | Files |
|---|---|---|
| R1 operator ran preflight after the freeze | The operator now follows the order that `protocol.json` and the README prescribe: init-check, paste of the bundled-skills list, preflight for A, B and C with `canary --source preflight`, `validate-refactors`, the offline gates once more, then the freeze, then the drive. A harness defect that only the preflight reveals can therefore still be fixed before any freeze exists. README now says the operator follows this order. | operator, README |
| R2 usage probe ran with the full user configuration | The probe now runs from an empty working directory with `--setting-sources ""`, `--strict-mcp-config`, an empty `--mcp-config` and `--tools ""`, like the benchmark calls, so it loads no user hooks, plugins or MCP servers. Whether the `rate_limit_event` is still emitted under these flags is not verified live (v1 transcripts show it under the adapter's isolated flags); an unreadable probe aborts at start and, in the watch loop, stops after three in a row. | operator |
| R3a preflight gate accepted an arm B that never ran | An arm record that is `unavailable` or has no call attempt fails the gate. | operator |
| R3b canary exit codes other than 0, 4 and 5 were only a warning | Any other status (a crash or unreadable output) aborts, in the preflight and in the drive. | operator |
| R3c `stop_driver` could leave scoring and browser processes behind | The driver is launched as its own session and process group and is stopped by group (TERM, then KILL), after its direct children; afterwards any process still listening inside this campaign's own port ranges (saved from `guard`, exact sub-ranges) is stopped. Tested with a synthetic driver and children in scratch; the listener parser was run on the real host, and found nothing in the campaign's ranges. Interrupt and terminate signals of the operator now run the same stop. | operator |
| R3d memory checked once at start | The watch loop samples free memory every five minutes and stops at the next cell boundary after two consecutive samples below 8 percent, or when swap used grows by more than 4096 MB over its value at the drive start (both configurable by environment variables). Memory and swap are logged every fifteen minutes. | operator |
| R4 canary conflated model non-adherence with harness failure | `canary_cell` fails arm C only on harness evidence (the generator skill was not invoked through the Skill tool, or a Skill call returned an error). A first arm C cell with no executed preflight or exploration step yields the new verdict `warn`; `canary_evaluate` reports it as a pass with the warnings kept (`warnings` list in the output). Arm A fails on a denied generator or browser tool call, an 'already used' port error, an infrastructure error, an isolation problem or a cost record that does not cover the stream; a cell where the model simply did not use the official tools is `pending`, and arm A fails only when none of its first three cells shows completed generator calls and a parent playwright test run. The operator logs the warnings. Tests cover each case, including a low-adherence first C cell passing. | runner, tests, protocol.json, README |
| R3a-style fixes already in R3 | The operator does not delete or move anything; a failed preflight must be moved aside by hand before a rerun, and the abort message says so. | operator |

Not changed: R5 (the generated-spec confound with `E2E_APP_PORT` and the fixed MCP port) is a documented limitation that needs no code; counting such specs in the summary is left to the owner. Stage and decision items from the build report stand.

Verified: 143 tests pass, `review.sh` 16 passed, the security gate 10 passed, `bash -n` and shellcheck clean on the operator, the preflight gate on synthetic records (good, unavailable B, infrastructure error on C), the stop logic on a synthetic driver. Not verifiable offline: the operator end to end, the probe under the new flags, and any live canary verdict.
