# Evidence-based reconciliation development protocol

Status: preregistered, not executed. This prospective development check does not replace the frozen subagent-routing pilot or establish accuracy, superiority, or release eligibility. Inline remains the default and delegation remains optional when uncertain; the changed decision is how contradictory evidence is reconciled.

Before evaluating any candidate response, freeze four paired source scenarios: the inline finding is refuted by a supplied helper; the delegated finding is refuted by a supplied config; neither verdict has enough source evidence; both verdicts agree but contradict the supplied implementation. Exchange actor labels in each pair without changing source. Use one fresh-context call per scenario and label ordering, eight calls total, no retries or outcome-selected replacements. Give only the current skill, raw source, and competing evidence to the evaluator. Record the complete skill digest, model/host identity, prompts, responses, omissions, and failures before interpreting results.

Acceptance requires source-grounded decisions invariant to actor labels, correction of a refuted finding regardless of origin, and explicit uncertainty when evidence is insufficient. Unresolved reviewer findings must not be emitted as confirmed; debugger output must preserve uncertainty instead of inventing a confident F-code. Any missed requirement makes this development check fail. No aggregate score, independent population claim, or release certification follows from eight synthetic decisions. Do not run this protocol against the observed cases used to motivate the change, and do not rewrite earlier protocols or their results.
