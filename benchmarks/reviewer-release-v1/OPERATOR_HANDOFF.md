## Roles and separation

| Role | Required independent contribution | Evidence required before a release claim |
| --- | --- | --- |
| Skill authors | Finish and test the isolated executor, complete transcript/provenance verifier, and clean evaluated commit; publish the exact protocol and verifier digest for preregistration | Reviewed commit, full repository gate, release-runner tests, disclosed protocol digest |
| External custodian | Select and seal 120 undisclosed cases outside the skill authors' control; keep source and oracle unavailable to authors and model-facing paths | Signed corpus commitment binding corpus, labels, two blind pre-run votes, tie-breaks, and custody ledger |
| Independent pre-run adjudicators | Two blinded votes per case, with a separate tie-breaker on disagreement and conflict exclusions | Votes and accepted source locations made before model outputs exist |
| Independent operator and online witness | Run the preregistered model and 1,080-call schedule in an isolated environment; keep signing key inaccessible to the model runner; sign `begin` before each model invocation and `end` after its exact outputs | Pre-run isolation attestation, online execution journal, signed input/output inventories, post-run attestation, isolation and key-custody evidence |
| Independent post-run adjudicators | Review arm-blinded, randomized responses using the resolved oracle, with two votes and a separate tie-breaker | Raw-hash-bound utility ledger, exclusions, tie-breaks, and inter-rater agreement |

The custodian and operator cannot be the skill authors. A signature produced later by the runner or by an author-controlled key does not establish independence or online timing. Development fixtures, public holdouts, and previous product-review packets cannot enter the sealed corpus.

The local witness client is a protocol adapter, not a witness. It sends one strict execution-event JSON payload to a Unix socket as a four-byte big-endian length followed by the exact payload bytes; it expects a four-byte length and one strict `{payload_base64, signature_base64}` receipt in return. The client reserves the receipt path before connecting, makes no retry, and checks the signature and exact payload hash using an independently pinned Go verifier before the model may launch or the next call may proceed. The verifier executable and every ancestor must be real, outside the runner user's ownership, and not group- or world-writable; a verifier copied under the runner's home or evidence bundle is rejected even if its initial hash matches. A local session helper enforces the frozen 2,160-event sequence, writes the exact verified response bytes to a create-only journal, and rejects reopening that bundle after a failed or interrupted session. The candidate 1,080-call coordinator now calls that helper at each begin/end boundary; only synthetic schedule and refusal tests cover this connection. The Go reference witness service can enforce the server-side schedule, artifact hashes, durable receipt journal, and duplicate-begin refusal when deployed by an independent operator with its signing key and journal outside the model runner and bundle. Its Unix socket accepts a separately provisioned runner-access group without making the private key or journal group-readable; the operator must establish real separate-user or separate-host custody, not merely pass a group ID. Local tests use disposable keys only; this repository does not operate such a service. The client cannot prove the external process's isolation, key custody, or live timing; the operator must supply those facts independently.

## Release admission sequence

**Artifact access is not provisioned by `--socket-gid`.** That option permits socket connections only. The candidate executor now requires `--witness-artifact-gid`; the reference service separately requires `--runner-uid` and `--artifact-gid`. Provision a dedicated read group for the distinct non-root runner and witness identities before execution. Do not reuse a broad login/staff group or infer independent custody from a group number. The service rejects root/same-UID identities and independently checks the owner, group and modes of signed artifact paths before hashing them.

The operator must provision a real bundle root and traversable ancestors with read-only group access, including the signed pre-run inputs the witness needs; the executor never recursively changes sealed input permissions. New `calls/<index>` and `inputs`/`outputs` directories use runner ownership, the declared artifact group and mode `0750`; only the four signed input files and five signed output files use `0640`. Runner auxiliaries, attempts, receipts and aggregate reports stay private. Witness key and operator journal remain private and outside the runner/bundle; socket parent `0710` and socket `0660` retain their separate connection boundary. Local membership/mode tests do not attest that the provisioned group has no additional principals or ACL grants: the independent operator must audit those facts.

Real distinct-UID integration of both `begin` and `end` has not run. The current host has no running Docker daemon; synthetic metadata and same-process tests cannot prove OS separation, key inaccessibility, or witness read-only access. Keep `DESIGNED_NOT_IMPLEMENTED` and `NOT_RUN` until the actual isolated deployment, not merely socket connectivity or unit tests, is validated.

1. Complete and independently validate the isolated executor and its negative-path tests. The candidate coordinator creates `bundle/calls` only after corpus admission and connects the one-call capture helper to witness callbacks. Its offline tests exercise the frozen `case → repetition → hash-ordered arm` schedule and fresh call roots, but do not prove release-grade isolation or real witness timing. The operator must enforce exactly one attempt and a 600-second wall limit per call. Any timeout, interruption, missing `begin`/`end`, unexpected tool, or incomplete trace makes the entire release run `INCONCLUSIVE`; never replace that call.
2. On a clean committed evaluated tree, independently pin the exact protocol SHA-256 outside the bundle and evaluated tree. The preregistered protocol snapshot must itself pin the Ed25519 public key and trusted verifier binary SHA-256. Freeze the runner image, model identity, isolation policy, and skill bytes. Do not silently edit an already frozen protocol.
3. The external custodian assembles `bundle.json` with hashed corpus/oracle/adjudication/custody references and signs the corpus commitment that binds those referenced bytes. Two independent pre-run adjudicators must certify the full scoring-valid finding set before any model call. The corpus is revealed only inside the isolated runner after the signed pre-run attestation verifies.
4. Pass the independently held digest to preflight as `validate-reviewer-release-v1.py --protocol <frozen protocol> --bundle <sealed bundle> --attestation-verifier <independently pinned binary> --expected-protocol-sha256 <preregistered digest>`, then pass that same digest to the candidate executor. Preflight refuses a missing or mismatched pin before checking the bundle. A `PASS (pre-execution-ready)` proves only the declared pre-run bundle and signature checks; the operator must separately establish actual isolation and key custody before dispatch.
5. The independent operator runs all 1,080 calls in the frozen order. The online witness signs each `begin` over the four already frozen input artifacts before launch and each `end` over the five output artifacts after completion. Preserve raw Codex JSONL, stderr, final bytes, MCP journal, and transcript report for every call. Do not expose corpus labels or other arm outputs to the model.
6. After execution, blind and randomize responses for two independent post-run adjudicators. Sign the response manifest, utility ledger, input/output inventories, execution journal, the exact JSON result of the finding-level matrix scorer, and the post-run attestation. Verify the Ed25519 chain and every bound file hash before running the offline call reconciler. The candidate attested-call bridge requires the same independently held `--expected-protocol-sha256`, recomputes the utility resolution and matrix score from signed inputs, and rejects a differing signed scorer result. It still reports consistency only; the operator must separately attest judge independence, live witness timing, and runner isolation.
7. Publish a release verdict only if provenance, completeness, adjudication, and every preregistered accuracy, lift, stability, helpfulness, and safety gate pass or fail on the complete 120-case matrix. Otherwise report `INCONCLUSIVE`, not a favorable subset or a development score.
