# Anonymous Notepad split-container transfer

Freeze this protocol and all `notepad-*` inputs plus `run_notepad_split.py` before execution. This is a transfer of one already demonstrated missing-save defect, not a new independent app/defect or a model-effectiveness evaluation. No model, install, image pull or CI is used.

Use pinned Anonymous Notepad commit `135e18dde6ac1acae195bb74dfaee49a0fbf33f6`, tree `979b6a731d64f7bdb15ebdea922b519d2710706f`. Each cell receives a fresh git archive. Only database storage is redirected to `/app-out/database.sqlite`; a fixed server entry binds loopback, records response-finish requests and closes SQLite after server shutdown. The original view/controllers/routes/models are preserved, except the fault controller removes exactly the one save after content assignment and records one owned hit. Dependencies are the read-only v7 Linux tree; require its complete digest, sqlite3 and bcrypt digests and successful recorded native gate.

App image is the cached v7 Cypress image, ID `sha256:a10a311fdac6a850603a4092842198356702ce77117569670dffe9f04ec8fd12`; it runs Node only. Test image is cached `e2e-generator-codex-v8:local`, ID `sha256:687b18c424d01c3af69efa921eaa824b48eb737d46492da334405e348da73881`, with the native Playwright runner and Chromium. Both must inspect successfully before Docker run; use immutable IDs with `--pull=never`. App network is none; test joins only its app's network namespace. No published ports. Source/deps are read-only; app-out is writable only in app, test-out only in test. Caps dropped, no-new-privileges, read-only roots, 2 CPU/1GiB/128 PIDs per container; browser `/dev/shm` 256MiB. Containers and artifacts are retained.

Run a fresh weak-normal canary first. Require native PASS, exact empty seed and persisted payload, one HTTP200 save and no hit. Then six new cells in this fixed order: weak-normal, weak-fault, weak-recovery, strong-normal, strong-fault, strong-recovery. Canary is setup evidence, not a seventh defect/sample. Payload is `Second OSS persistence control 20261018`; endpoint `second-oss-control`. The app's initial getNote seeds the row. A host Python SQLite read-only/query-only oracle observes exactly one empty row before acknowledging the test's file barrier. The test then fills once; weak checks editor echo, strong reloads and checks persisted text.

Expected weak fault survives with empty SQLite content and hit1. Strong fault fails solely at `note-content-persisted-after-reload`, expected payload/received empty. Every normal/recovery passes with persisted payload and hit0. All tests have one attempt, zero retries, one trace, one target POST/content payload/status200. Host after-stop oracle requires DELETE journal, no nonempty WAL, quick_check ok and exact row. Native JSON report, trace, source hashes, server request log and stopped container inspections must corroborate. Stop at first unexpected outcome, timeout or missing evidence; preserve it, do not retry/retune. An independent verifier must admit each cell before proceeding beyond the canary.

Host and Docker disk must have >=4GiB, host load1<8 and used swap<4096MiB. App readiness <=12s, test wall time <=55s, shutdown <=8s, entire sequence <=600s excluding preflight hashing. Freeze unrelated-container snapshots before/after; any drift invalidates the sequence. Verify dependencies, source checkout and frozen inputs unchanged after each cell. This runner requires an explicit `--execute` flag and an existing independent verifier path; no execution occurs on import or without the flag.

Artifacts: output root `frozen-inputs.json`, `preflight.json`, `unrelated-before.json`, `unrelated-after.json`, `results.json`, `artifacts-sha256.json`. Each named cell has `app/`, `app-out/{database.sqlite,requests.jsonl,server-ready.json,server-stopped.json,hits.txt?}`, `test-out/{report.json,runner.stderr,trace/**/trace.zip,observation.json,seed-ready,seed-continue}`, `before.json`, `after.json`, `oracle.json`, `source-hashes.json`, `app.id`, `test.id`, `app-inspect.json`, `test-inspect.json`, `execution.json`, `verification.json` and raw Docker/app logs. On interruption/error, `failure.json` records the exception; incomplete artifacts remain invalid.
